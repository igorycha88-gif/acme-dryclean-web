# ЧТЗ (упрощённое) — Фикс деплоя: нехватка диска на VPS (852MB < 1GB)

**Дата:** 2026-08-18
**Маршрут:** Постдеплойный рестарт: Аналитик → Разработчик → Тестировщик → DevOps
**Тип:** малая инфраструктурная задача (1 файл)

## 1. Проблема

Хотфикс-деплой `8ae2440` упал на pre-flight: `Insufficient disk space:
852MB free (need 1GB)`. Прод работает на предыдущей версии (безопасно,
blue-green не затронут).

**Причина:** cleanup старых образов в deploy-vps.sh выполняется только в
КОНЦЕ успешного деплоя; при заполненном диске деплой не стартует → cleanup
никогда не выполняется → взаимоблокировка.

## 2. Решение

Добавить «Step 1.1: Docker image cleanup» в deploy-vps.sh — ПОСЛЕ
`source .env`, ДО дискового гейта:
- `docker image prune -f` (dangling-слои)
- удаление старых тегированных образов `ghcr.io/*dryclean` с сохранением
  4 новыхейших (по аналогии с существующим end-cleanup, где KEEP_IMAGES=10)
- повторный `docker image prune -f`
- логирование freed-объёма

Безопасность: `docker rmi` образов запущенных контейнеров завершится
ошибкой и пропустится (`|| true`) — работающий прод не затрагивается.

## 3. Файлы для изменения

- `scripts/deploy-vps.sh`

## 4. Критерии приёмки

- AC-1: `bash -n scripts/deploy-vps.sh` — синтаксис OK
- AC-2: Cleanup выполняется до дискового гейта
- AC-3: Повторный деплой проходит pre-flight и завершается успехом
- AC-4: Прод после деплоя: сайт 200, `/price-list.pdf` в футере новой сборки

## 5. План отката

revert одного коммита; прод не затронут до следующего деплоя.
