# ЧТЗ: Закрытие публичных портов на VPS (Network Hardening)

**Дата:** 2026-08-07
**Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps
**Приоритет:** CRITICAL
**Тип:** Инфраструктурный фикс безопасности

---

## 1. Описание проблемы

Публичный сервер `37.143.15.148` (da-dryclean.ru) экспонирует во внешнюю сеть порты сервисов, которые должны быть доступны только локально (через nginx):

| Порт | Сервис | Уязвимость |
|------|--------|------------|
| 3000 | Frontend (Next.js) | Прямой доступ в обход nginx |
| 8011 | Content API | `/health`, API-эндпоинты доступны всем |
| 8020 | Tracking service | uvicorn-сервер торчит наружу |
| 9090 | Prometheus | Утечка метрик и внутренней архитектуры |
| 3030 | Grafana | Публичная страница логина, брутфорс |

**Причина:** Docker-контейнеры запускаются с `-p ${PORT}:PORT`, что привязывает порт к `0.0.0.0` (все интерфейсы).

---

## 2. Решение (двухслойная защита)

### Слой 1: Привязка портов к localhost

Все `-p ${PORT}:PORT` → `-p 127.0.0.1:${PORT}:PORT` в `scripts/deploy-vps.sh`.
Это гарантирует, что контейнеры слушают только на loopback-интерфейсе.

**Затронутые порты (12 вхождений):**
- Content: 8011, 8012 (green)
- Tracking: 8020
- Frontend: 3000, 3001 (green)
- Prometheus: 9090
- Grafana: 3030

### Слой 2: UFW Firewall (defense-in-depth)

Добавить шаг настройки UFW в начале деплоя:
- Default: deny incoming, allow outgoing
- Allow: 22 (SSH), 80 (HTTP), 443 (HTTPS)
- Enable UFW
