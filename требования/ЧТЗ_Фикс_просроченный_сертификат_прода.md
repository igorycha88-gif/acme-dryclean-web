# ЧТЗ: Аварийное восстановление прода — истёкший TLS-сертификат + диск VPS

**Дата:** 2026-08-19
**Маршрут:** 3 (инфраструктурный) — Аналитик → DevOps
**Исполнитель:** DevOps
**Приоритет:** CRITICAL (прод недоступен по HTTPS с 03:16 GMT 2026-08-19)

## 1. Описание проблемы

1. **CRITICAL:** TLS-сертификат Let's Encrypt для `da-dryclean.ru` (+ www) истёк
   2026-08-19 03:16 GMT. Браузеры блокируют сайт, все HTTPS-клиенты получают
   ошибку сертификата (verify error:num=10: certificate has expired).
2. **HIGH:** Свободное место на VPS < 1GB (852MB) — деплой hotfix падал на
   disk-space gate (deploy-vps.sh, Step 1).
3. **MEDIUM:** Hotfix прайс-листа (commit bcc2aa9) не задеплоен — последний
   деплой упал на транзиентном SSH timeout с раннера.

**Первопричина №1:** архитектура деплоя переехала на `docker run` + хостовой
nginx (deploy-vps.sh), а compose-certbot из docker-compose.prod.yml (который
делал `certbot renew` каждые 12h) больше не запускается. Автопродление
сертификата фактически отключено.

## 2. Что сделано ранее (контекст)

- bcc2aa9 уже добавил prune образов ДО disk-gate (Step 1.1 в deploy-vps.sh) —
  эта часть починки диска уже в main, но не доставлена на VPS.

## 3. Задачи

- **TASK-INF-001:** `scripts/renew-cert.sh` — идемпотентный скрипт продления
  сертификата (webroot, certbot на хосте или через `docker run certbot/certbot`
  с host-маунтами). Порог: < 30 дней до истечения. После renew — `nginx -s
  reload` + верификация дат.
- **TASK-INF-002:** Интеграция в `scripts/deploy-vps.sh` (Step 1.15, ПОСЛЕ
  prune, ДО disk-gate — чтобы починка не блокировалась диском).
- **TASK-INF-003:** `.github/workflows/cert-renew.yml` — cron 2 раза/сутки,
  SSH на VPS, запуск renew-cert.sh, Telegram-уведомление при провале.
- **TASK-INF-004:** SCP-синхронизация `scripts/renew-cert.sh` в deploy.yml
  (source-список scp-action).
- **TASK-INF-005:** Деплой на прод: push в main → `gh workflow run deploy.yml`.
  Деплой: prune → renew cert → blue-green deploy → smoke.

## 4. Критерии приёмки

- [AC-1] `curl -sfI https://da-dryclean.ru/` → HTTP 200 (с любого внешнего клиента)
- [AC-2] Сертификат валиден ≥ 60 дней (не раньше notBefore 2026-08-19)
- [AC-3] SAN: da-dryclean.ru + www.da-dryclean.ru
- [AC-4] Деплой bcc2aa9+ доведён: в футере живого сайта ссылка `/price-list.pdf`
  (а не `/api/price-list`), файл отдаётся (200)
- [AC-5] Все smoke-тесты деплоя PASS (content/frontend/tracking/prometheus/grafana)
- [AC-6] Свободное место на VPS ≥ 1GB после prune
- [AC-7] cert-renew.yml существует, cron активен, вручную запускался без ошибок

## 5. Риски и митигация

| Риск | Митигация |
|------|-----------|
| SSH с раннера снова таймаутит | Порт 22 открыт, VPS отвечает; при повторе — ручной ранбук пользователю |
| Certbot webroot-челлендж не пройдёт (нет /var/www/certbot на хосте) | `mkdir -p`; nginx :80 уже отдаёт /.well-known (prod.conf:55) |
| Rate limit LE (5 dup/week) | --force-renewal только при <30д; после успеха скрипт no-op 60 дней |
| Сломать рабочий деплой | renew-шаг логирует всё, fatal только если сертификат остаётся битым |
